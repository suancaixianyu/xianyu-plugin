# Legacy Migration

本文记录 `D:\yunza\xianyu-plugin-master` 老版本到当前 AlemonJS 架构的迁移判断，目标是后续按游戏逐个迁移，而不是整仓平移旧框架。

## 老版本结构

- 框架入口
  - `index.js`
  - 运行时扫描 `apps/*.js`
- 命令定义
  - `config/command.js`
  - 通过正则数组为每个游戏分发命令
- 公共工具
  - `res/api.js`
  - YAML/JSON 读写、按钮开关、统计上报、深拷贝
- 游戏实现
  - `apps/*.js`
  - 每个文件是一个 Yunzai `plugin` 类
- 资源与模板
  - `public/html/*.html`
  - `public/html/img/*`

## 迁移原则

- 迁移“游戏规则、命令语义、资源素材”，不迁移旧框架壳
- 新版统一接入
  - `src/api/gameRegistry.ts`
  - `src/api/gameSession.ts`
  - `src/api/gamePools.ts`
- 命令要重新组织为
  - `routes`
  - `compactRoutes`
  - `controller.rewriteCommand`
- 旧版全局群状态要改成新版作用域状态

## 游戏盘点

### 已优先确认

- `扫雷`
  - 老版本文件：`apps/扫雷.js`
  - 当前状态：已迁移并接入新架构
  - 特点：单人棋盘类，短指令冲突明显，已用于验证会话接管

- `24点`
  - 老版本文件：`apps/24点.js`
  - 当前状态：本轮迁移
  - 特点：纯文本、无图片、状态最轻，适合作为第一个非扫雷迁移样本

### 优先级较高

- `推箱子`
  - 老版本文件：`apps/推箱子.js`
  - 特点：单人状态、撤回和关卡列表清晰
  - 迁移判断：适合在 `24点` 之后迁

- `五子棋`
  - 老版本文件：`apps/五子棋.js`
  - 特点：双人对战、指令简单
  - 迁移判断：适合用来验证多人回合模型

- `斗兽棋`
  - 老版本文件：`apps/斗兽棋.js`
  - 特点：双人棋盘、规则中等复杂度
  - 迁移判断：可在五子棋之后处理

### 建议后置

- `中国象棋`
  - 老版本文件：`apps/象棋.js`
  - 特点：多人队伍、悔棋、中文棋谱、判定器复杂
  - 迁移判断：重度业务迁移，建议后置

- `国际象棋`
  - 老版本文件：`apps/国际象棋.js`
  - 特点：多人队伍、规则判定器、棋盘渲染
  - 迁移判断：与中国象棋类似，建议后置

### 非核心游戏或功能

- `恶魔轮盘`
  - 老版本文件：`apps/恶魔轮盘.js`
  - 迁移判断：待单独评估

- `统计`
  - 老版本文件：`apps/tongji.js`
  - 迁移判断：不属于核心小游戏，后续再看

- `帮助`
  - 老版本文件：`apps/help.js`
  - 迁移判断：应合并到当前帮助系统，不单独迁

- `更新`
  - 老版本文件：`apps/更新.js`
  - 迁移判断：与当前项目运行环境不一致，不建议直接迁

## 当前结论

- 最适合先迁的真实样本是 `24点`
- 下一批最适合迁的是 `推箱子` 或 `五子棋`
- `中国象棋`、`国际象棋` 要等多人会话和棋盘渲染策略更稳定后再做
